# AbyssProtection 1.0 TEST — Fabric 26.3
Source only; build with GitHub Actions (Java 25). Not compiled or runtime tested here. Use a disposable test world, not production.

Console: `ap give Player 512 1` or `ap give Player 512x256 1`. OP or LuckPerms abyssprotection.admin / abyssprotection.protection.give. Players can place issued blocks without give access. Limits: abyssprotection.limit.N, abyssprotection.limit.unlimited; default 1. Right-click marker or /ap settings. /ap add NAME, /ap remove NAME, /ap members, /ap info, /ap list, /ap hide, /ap show, /ap rename NAME, /ap transfer NAME. Add/transfer currently online only. Member menu removes members; add via command. Flags for visitor actions; owner and members bypass ordinary interaction flags. PvP applies to everyone. Hidden marker must be shown before recovery. Data stored in config/abyssprotection/data.json. Optional AbyssGuard FIX13 overlap check uses public region fields, fails closed if incompatible.

Known limitations: experimental explosion hook (conservative 32-block margin, not guaranteed); piston/hopper, crafting conversion, creative copying, per-member permissions, exact placement interception, full GUI customization, border display, admin deletion/reload and complete anti-grief coverage are not finished. Do not rely on this version to protect live builds. Duplicate active token placement is rejected, but copied inactive tokens and crash consistency need further testing. Flags for pistons are not enforced yet. Test normal block placement, recovery, restart, GUI, LuckPerms and overlaps first.
